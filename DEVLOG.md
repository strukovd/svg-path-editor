# Хроника проекта

## 2026-06-16

### Где сейчас проект

Проект постепенно переезжает от редактора одного `path` к редактору SVG-сцены целиком.

Нейминг уже начал меняться с `Editor*` на `Scene*`:

- `SceneStore` хранит сцену, камеру, элементы и историю.
- `SceneComponent` отвечает за основное SVG-полотно.
- `PropsBar` становится панелью свойств активного элемента.
- `BaseIsland` добавлен как общий блок-секция для панели свойств и похожих UI-островков.

### Контейнер выделения / bounding box

Последняя крупная линия работы была вокруг контейнера выделенного элемента.

Идея: не копировать код выделения, перемещения, resize и других возможностей в каждый элемент, а вынести это в общий слой:

- `useSelectable`
- `useMovable`
- `useResizable`
- `useRotatable`
- `useTransformable`
- `SceneEntityBox`

Важное решение: bounding box лучше делать не буквальным родителем SVG-элемента, а отдельным фальшивым overlay-элементом (фальшивкой) рядом с фигурой. То есть контейнер рисуется поверх/рядом по координатам выбранного объекта и управляет им через данные, а не через вложенность SVG-разметки.

Причина: SVG-элементы могут быть разными (`rect`, `image`, `path`, группы), и общий контейнер не должен ломать их структуру или требовать одинаковой верстки.

### Single select и multi select

Для одного выбранного элемента контейнер может показывать полный набор возможностей:

- move
- resize
- scale
- rotate
- opacity
- lock/remove

Для мультивыбора нужен другой контейнер: он должен строиться по общей рамке нескольких элементов и иметь другой набор действий. Не все возможности одиночного элемента корректно переносятся на группу без отдельной логики.

### Reference image

Была добавлена возможность работать с картинкой-референсом. Из нее появился красивый контейнер управления, который затем захотелось вынести в общий компонент/композаблы.

После этого возникло новое решение: `image` логичнее сделать обычным элементом сцены, а не отдельной сущностью только для обрисовки. Тогда картинку можно будет:

- выделять тем же контейнером;
- двигать и трансформировать тем же механизмом;
- хранить в сцене вместе с остальными элементами;
- экспортировать в итоговый SVG.

### Почему пока не path

`path` сложный: у него своя внутренняя структура команд, точки, контрольные точки, редактирование сегментов и отдельная логика.

Поэтому ближайший практичный шаг: сначала добавить простые примитивы сцены и отточить общий контейнер на них:

- `rect`
- `image`
- возможно `circle`, `ellipse`, `line`

Когда контейнер, выделение и базовые трансформации будут нормально работать на простых элементах, можно безопаснее возвращаться к `path`.

### Ближайший фокус

1. Вернуть проект в компилируемое состояние.
2. Добавить простые элементы сцены (`rect`, `image`) как полноценные `SceneElement`.
3. Довести общий контейнер выделения на простых элементах.
4. После этого двигаться к `Svg.parse(text)` и импорту нескольких `<path>`.

### Технические долги на тот момент

- `SceneComponent` вызывает `startDragPoint`, но функция сейчас закомментирована.
- Есть конфликт файлов `src/lib/svg.ts` и `src/lib/Svg.ts`, которые отличаются только регистром.
- `SceneStore` хранит классовый `Path` в reactive state, из-за чего TypeScript/Pinia ругается на типы.
- `PropsBar` частично нужно привести к правилам из `AGENTS.md`: стили должны быть вложены по HTML-иерархии.

## 2026-06-17

### Отключение legacy Path от активной сцены

Старый `Path`-слой временно убран из активной модели сцены. Файлы `src/lib/svg.ts`, `path-parser.ts` и связанные утилиты остаются как reference/legacy, но `SceneStore` больше не хранит классовый `Path`.

Новая активная модель сцены строится на plain object элементах:

- `rect`
- `line`
- `circle`
- `ellipse`
- `image`

Это нужно, чтобы сначала отточить общий слой сцены, выделение, контейнер трансформации и ручное рисование на простых элементах. `path` вернется позже как один из элементов, а не как центр всей архитектуры.

### Состояние сцены

`SceneStore` теперь хранит:

- `elements`
- `selectedIds`
- `editableId`
- `mode`
- `tool`
- `history`

История пока сделана через полные snapshot-снимки сцены. Это проще и надежнее на этапе, где модель элементов еще меняется.

Закрыто из предыдущих долгов:

- `startDragPoint` больше не вызывается из активной сцены.
- `SceneStore` больше не хранит классовый `Path`.
- Черновик `src/lib/Svg.ts` переименован в `src/lib/svg-document.ts`, чтобы не конфликтовать с `src/lib/svg.ts`.

### Следующий фокус

Следующий практичный шаг - добавить режим ручного рисования:

1. Выбор инструмента на панели (`rect`, `line`, `circle`, `ellipse`).
2. `mousedown` на сцене создает `draftElement`.
3. `mousemove` обновляет черновик.
4. `mouseup` добавляет элемент в `elements` и пушит snapshot в историю.

## 2026-07-10

### EntityBox для одиночного выбора

Подключен первый вариант `EntityBox` как overlay-слой `transform-layer`.

Текущий поток:

1. Основной слой `elements` рисует обычные SVG-элементы.
2. Клик по элементу вызывает `selectElement(id)`.
3. `SceneStore` переводит редактор в `mode = 'transform'`.
4. `SceneComponent` берет выбранный элемент и через `getElementBox(element)` получает его общий `SceneBox`.
5. `SceneEntityBox` рисуется поверх элемента как фальшивый overlay.
6. Move/resize box-а отправляет новый `SceneBox` обратно в `SceneStore`.
7. Store применяет box к элементу через `updateElementBox(element, box)`.

Важное решение осталось тем же: `EntityBox` не является родителем SVG-элемента. Он рисуется рядом/поверх и управляет элементом через адаптеры.

### Адаптеры элементов

Добавлен мост в `src/lib/scene/elements.ts`:

- `getElementBox(element)`
- `updateElementBox(element, box)`

Пока это первый простой вариант для `rect`, `line`, `circle`, `ellipse`, `image`. Для `line` resize сейчас нормализует линию от верхнего левого угла box к нижнему правому; позже поведение можно уточнить.

## 2026-09-03

### Динамические панели редактора

Начат слой UI-состояния редактора через `EditorStore`.

`EditorStore.panels` теперь хранит не строки, а описания видимых правых панелей:

- `key` - имя Vue-файла панели в `components/common/scene/panels`.
- `title` - заголовок, который показывает `BaseIsland`.

Наличие элемента в `panels.items` означает, что панель включена. Отдельный `visible` флаг пока не нужен.

`PropsBar` проходит циклом по `editorStore.panels.items`, оборачивает каждую панель в `BaseIsland` и подставляет компонент через `<component>`.

Компоненты панелей грузятся лениво через `loadPanelComponent()` из `src/utils/asyncLoaders.ts`. Для `import.meta.glob()` нужна явная типизация `{ default: Component }`, иначе Vite/TypeScript видит loader как `() => Promise<unknown>` и `defineAsyncComponent()` ругается на типы.
