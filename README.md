# ⚙️ Концепция проекта
Концепция нужна что бы не путаться и интуитивно понимать что где искать.

Приложение делится на иерархию модулей (домены).
Глянем сразу (модулей не много):
```
App (Главная страница, знает о своих: menu, toolbar, scene, sidebar, footer)
└── Scene (Центральная часть экрана, основная сцена, знает о элементах на сцене, какие выбраны, какой редактируется, ..)
    └── Element (SVG-element, знает свойства элемента, типа: цвет,прозрачность, .., знает как рисовать и редактировать каждый вид элементов )
```

Иерархия кажется понятной и логичной, и кажется что если нужен - масштаб сцены,
то его нужно искать в КОМПОНЕНТЕ сцены..
НО! не торопитесь искать его там.

Если бы я всё хранил в компоненте, компонент бы стал свалкой, в которой невозможно было бы разобраться.

Поэтому - понятие модуля делится на сущности:
```
┌────────────────────────┐
│ 						 │
│ 🟩 компонент (vue),	 │
│ 🟨 стор (pinia),		 │
│ 🟪 композаблы.		 │
│ 						 │
└────────────────────────┘
```

А теперь подробнее..

### Зачем это нужно?
- Компонент не сможет хранить все данные\состояния и методы в себе:<br>
1. Во первых, это сложно читается, код компонента превращается в свалку<br>
╰┈> декомпозируем логику блоками, выносим в composables.<br>
`То есть мы осуществляем вынос методов «за контур» компонента, с сохранением доступа и владения в контексте одного модуля.`
<br><br>
1. Нужен порядок\иерархия для логики, что бы сразу было понятно, кто за что отвечает.<br>
╰┈> Делим на модули<br><br>
1. Большинству других компонентов (виджетов) в проекте, нужно знать внешние значения (например модулю настроек)
2. Компонент работает экземплярами, а что бы хранить доступное значение нужен singleton (единый экземпляр)<br>
╰┈> Выносим такие значения в Pinia, которая даст singleton (единый экземпляр) и привычное использование<br><br>

❗ ИТОГО, складываются правила:
- Поля храним в `🟨 store` для глобальной доступности (singleton)
- Методы храним в `🟪 composable` для декомпозиции на части (остается более читаемый компонент)
- `🟩 Компонент` может содержать поля и методы, но только если они небольшие, и точно не нужны снаружи (другим компонентам)


## Точка входа
В [SceneStore.ts](/src/stores/SceneStore.ts#L5-L6) определен path рисунок




Разбор структуры:
Есть один SVG, внутри которого сначала рисуются линии (<line>, только в пределах видимости, сначала жирные 0, 0, затем остальные), затем рисуется обыкновенный path, внутрь которого помещается провализированный код из редактора, затем рисуются поперечные линии (<line>) (для кривых безьё), а затем уже сами точкт (<cirle>) всех элементов (линий, безьё, arc, и прочее)
